# Agent 增强十二维框架——以一个跑了 3 个月的生产 Agent 为样本

**定位**：市面上讲 Agent 的内容九成在讲「怎么用」，这份讲「怎么比别人强」。所有人用的都是同几个模型，差距不在模型，在模型外面那一圈系统。

**样本**：Hermes Agent，跑在腾讯云 4C/3.6G/40G 服务器上，2026-08 至今真实生产运行（金融推送、内容生产、安全审计、自进化循环），以下每条结论都有实机数据或翻车记录背书，不抄网文。

**框架总览**：

| 层 | 维度 | 决定什么 |
|---|---|---|
| 静态层（出厂配置） | ①人设 ②工具 ③搜索 ④记忆 ⑤模型选择 ⑥专业知识库 | agent 的能力上限 |
| 动态层（运行机制） | ⑦执行纪律 ⑧记忆写入口径 ⑨自我进化 ⑩安全边界 ⑪多agent编排 ⑫失效判据 | 越用越强还是越用越歪 |

一句话：静态层决定它「能做什么」，动态层决定它「跑三个月后是资产还是负债」。

---

# 第一部分：静态层——六个出厂配置

## ① 人设（System Prompt / SOUL）

**原理**：人设不是角色扮演化妆，是行为约束系统。同样一个模型，人设里写「你是助手」和写「你是带铁律的专家系统」，输出质量差一个档次。人设 = 身份定位 + 行为铁律 + 禁区清单。

**我的做法**：SOUL.md 只放三类东西——不可妥协的铁律（如「一切判断基于当下时间节点，可查询的事实一律工具亲验」）、语气人格（尖锐、直给、可以吵架）、和持久事实（用户偏好、环境硬约束）。Soft 的东西全部外置到技能，不塞人设。

**实测收益**：人设里那条「实时亲验」铁律，是全系统收益最高的一行字——它把「模型用训练记忆里的旧数据糊弄」这类错误压到接近零。反面教材：早期没有铁律时，模型报的版本号、日期、行情全是编的。

**最小抄作业**：写 5-10 条铁律，每条都是「禁止 X / 必须 Y」的可判定的规则，不要写愿景和形容词。「你是一个乐于助人的助手」= 零信息量。

## ② 工具（Tooling）

**原理**：agent 的能力边界 = 工具边界。模型智商再高，没有手就是瘫痪的先知。工具质量的排序：官方 API/CLI > 结构化脚本 > 网页抓取 > 无头浏览器闯关。

**我的做法**：三层工具栈——CLI 优先（gh、bl、tccli 等官方 CLI，稳定且防封号）、脚本层（自建 Python 管线，如数据采集/文档推送）、浏览器只做最后手段。每个工具带「坑位记录」（如 GFW 下 GitHub push 必挂改走 gh api、sqlite3 CLI 被劫持改用 python stdlib）。

**实测收益**：坑位记录比工具本身值钱。同一个工具，知道「哪个通道在哪个网络环境下会挂」和不知道，是可用和不可用的区别。反面：早期凭直觉用第三方库，静默失败三次才发现工具坏了——「某功能最近才坏，先测外部命令本身」从此成为铁律。

**最小抄作业**：每引入一个新工具，先做 ROI 评估 + 资源评估（磁盘/内存/是否常驻），并把第一次踩的坑写进工具的使用说明。工具不记坑 = 没装。

## ③ 搜索（Search）

**原理**：搜索质量决定信息的时效与真假。单引擎搜索是 2010 年代的玩法，生产级 agent 需要多引擎 + 降级链 + 时效判据。

**我的做法**：搜索三件套——多引擎冗余（主引擎挂了自动换源）、渠道实测档案（哪个搜索引擎对中文/英文/GFW 环境最稳，逐个实测记录）、时效判据（数据最新一期距今天数超过阈值 = 视为失效，宁可不报）。

**实测收益**：抓过一个真 bug——某宏观源冻结一年不更新但不报错，模型照常引用。「判据 = 最新日期距今 ≤ N 天」这条规则救了所有下游推送。反面：数据源静默失效是常态不是例外，任何「不报错」的数据源都要主动验活。

**最小抄作业**：给每个常用数据源写一行「最后验证日期 + 判活方法」，搜索结果落地前过一遍时效检查。

## ④ 记忆（Memory）

**原理**：记忆让 agent 跨会话累积。但记忆系统的重点不在「存」，在分层——什么该永久、什么该过期、什么只属于当前任务。

**我的做法**：双轨记忆。注入层（每次会话自动加载的高信号事实，严格限字符数）+ 检索层（全量库，按需搜索，含向量 + 全文混合检索）。再加结构化层：身份卡（单一事实源，防自我矛盾）、知识图谱三元组（subject-predicate-object，带有效期）、任务进度追踪（跨会话的「做到哪了」）。

**实测收益**：跨会话连续性从零到满。翻车记录也真实：运行环境升级（Python 解释器更换）导致记忆服务静默挂掉，模型没记忆了还不自知——教训是「记忆服务本身要进每日健康检查」。记忆是基建，基建也会塌。

**最小抄作业**：至少做两层——一个每次自动加载的小文件（<2000字，只放高信号事实），一个可搜索的全量库。所有记忆写成「陈述句事实」而非「指令」，指令会被当命令重新执行造成污染。

## ⑤ 模型选择（Model Routing）

**原理**：全用一个旗舰模型是烧钱且不必要的。生产 agent 需要模型池：不同任务路由到不同档位的模型，旗舰只用在刀刃上。

**我的做法**：分层模型池——主力模型（日常对话，性价比档）、定时任务模型（推送类，再降一档）、降级备胎（主模型挂了自动切换）、专项模型（视觉/压缩等独立配置）。切换有专用脚本，验收不只看探活（探活全绿也可能路由已静默失效），要看真实计费记录。

**实测收益**：成本降一个数量级，质量无感损失。最大的坑是「静默降级」：provider 名写错一个字母，每条消息都在偷偷用备胎，探活还全绿——发现方式是查计费日志而不是测连通性。验收路由配置必须看账单，不能信绿灯。

**最小抄作业**：主模型 + 一个 fallback 起步，规则一句话——「便宜模型跑量，贵模型跑判断」。改配置后查一次真实用量日志再宣布生效。

## ⑥ 专业知识库（Skills / Domain Knowledge）

**原理**：这是和「别人的 agent」拉开差距的最大杠杆。通用模型什么都会一点，专业库里沉淀的「你专属的工作流 + 踩坑记录」是别人无法复制的数据资产。

**我的做法**：技能库 = 流程知识（一个任务的标准作业程序）+ 坑位知识（每个流程的失败模式与修复法）+ 参考资料。加载机制用渐进披露——只有描述常驻上下文，匹配任务才加载全文，控 token。技能来源三分：社区装机的（装前审计）、自建的（复杂任务后主动沉淀）、社区的 + 自己改的（最常见）。

**实测收益**：一次踩坑沉淀成技能后，同类任务从「重新踩一遍」变成「直接绕开」。审计过 10 个社区热门技能，10 个都有高危缺陷——结论：社区技能不是拿来就用，是拿来审再用。知识库的复利本质：每个任务的教训都可被后续所有任务复用。

**最小抄作业**：从「你重复做过三次以上的事」开始建第一个技能。判断标准：这个任务你愿意每次都用同样方法做 → 值得沉淀；每次做法都不同 → 不值得。

# 第二部分：动态层——六个运行机制

## ⑦ 执行纪律（防幻觉机制）

**原理**：权重最高的一维。模型的一切能力都要经过「会不会一本正经编造」这个漏斗过滤。纪律层缺失的 agent，工具再多也是高级胡说机。

**我的做法**：五条硬纪律——①可查询的事实必须工具亲验，禁止凭训练记忆回答；②算术/哈希/系统状态/当前时间禁止心算，必须跑工具；③输出分「验证过 ✓ / 没验证 ⚠️」两级标注；④发现数据错误立即承认修正，不狡辩；⑤工具结果为空或可疑时，换策略重试而不是编一个交差。

**实测收益**：这是玩具 agent 和可托付 agent 的第一分水岭。数据零容忍执行三个月，用户信任的根基全在这。反面案例历历在目：模型曾把「探活全绿」当「路由正常」，实际计费显示一直在用错模型——不亲验账本就敢下结论，就是纪律缺失。

**最小抄作业**：把「禁止心算、必须亲验、没验证要声明」三条写进系统提示最高优先级位置，并配一条元规则：「说不知道，好过编一个」。

## ⑧ 记忆的写入口径（Memory Hygiene）

**原理**：记忆系统崩坏不是因为不够大，是因为写入不设防。三个月后一半条目过时、两条互相矛盾、十条废话——检索时垃圾把金子淹没。

**我的做法**：写入口径四问——该不该记（一次性任务进度不进长期记忆）、记在哪一层（永久身份 / 普通事实 / 临时便签）、什么时候失效（时间敏感的结论带过期日期）、和旧条目什么关系（取代要显式声明，不并行保留两个版本的真相）。配套定期巡检：每日自动巡检 + 定期矛盾消解。

**实测收益**：避免过的真实事故——「某端口走 22」的旧结论和实测矛盾，若不显式作废旧条目，每次检索都会把错误答案递回给模型。失效的结论不删除而是标记作废（保留历史），但检索排序必须让新结论压过旧的。

**最小抄作业**：立一条规矩——每个新记忆写入前先问「这条半年后还对吗」，不对就带过期日期。每月清一次明显过时的条目。

## ⑨ 自我进化（Self-Improvement Loop）

**原理**：静态配置会过时，进化机制让系统自己追平环境变化。核心不是「每周跑个优化脚本」，是任务结束后的即时沉淀。

**我的做法**：三级循环——①在线 refine：复杂任务（5+ 次工具调用）做完立即提炼教训，沉淀进技能/记忆；②每周体检：定时任务跑技能进化评估 + 11 项偏误体检（产物新鲜度、内容指纹防复读、推测混实测检查、结论保鲜复测）；③失败入账：每个翻车案例写进失败账本，附根因和修复法。

**实测收益**：体检抓到过真实 bug：定时推送的静默标记被模型「翻译」成中文导致垃圾内容直投用户——这种问题靠人盯永远发现不了。但要泼冷水：进化循环也有翻车面，自动优化器曾对已归档的技能空转一周，holdout 提升在评测噪声内被误读为进步——进化机制本身也要配「防止假装进步」的判据。

**最小抄作业**：先只做第一级：规定「任何复杂任务完成后，花一分钟把可复用的流程写进知识库」。这一条的复利超过后面所有高级玩法。

## ⑩ 安全边界（Security & Supply Chain）

**原理**：给 agent 装第三方技能 = 让陌生人对你的系统写指令。agent 的攻击面 = 所有工具权限之和 + 所有外部内容的注入面。做增强的人九成不考虑这维，这是最容易被人一锅端的维度。

**我的做法**：四条防线——①装前审计：第三方技能逐条审（隐藏内容扫描：HTML 注释/零宽字符/双向文本注入；脚本失败语义；凭据禁区）；②输入侧防护：抓取脚本加协议+域名白名单+解析 IP 校验+重定向逐跳验证；③权限最小化：组件按需拉起不常驻，密钥文件 0600，定期清理明文密钥残留；④威胁模型成文：明确哪些风险已修、哪些明确接受（如 DNS rebinding 的 TOCTOU 窗口），不装不知道。

**实测收益**：审计 10 个热门社区技能全数命中高危缺陷，包括从邮箱自动取验证码（等于绕过双重验证）。自己代码经外部红队复审修出 7 处真缺陷——其中「空快照会误删整棵依赖树」这种，没有审计流程就是等事故。

**最小抄作业**：立三条：装任何第三方扩展前必审（至少扫隐藏字符和外部 URL）；agent 能跑命令就把命令注入当默认威胁；写一页威胁模型说明「我防了什么、明确接受什么」。

## ⑪ 多 Agent 编排（Orchestration）

**原理**：单体 agent 上下文一炸就废，并行任务互相污染。规模化必修：把大任务拆给隔离子代理，各带独立上下文，主 agent 只收摘要。

**我的做法**：分工矩阵——推理重/上下文重的子任务派子代理（各自独立会话），机械批量任务用纯代码不用模型（省 token 且零幻觉），关键步骤保持串行防依赖错序。关键纪律：子代理的汇报是自报不是事实，涉外部副作用的结论必须回读验证（子代理说「上传成功」不算数，要自己看到 URL）。

**实测收益**：并行拆分后，多线任务的墙钟时间减半以上；机械任务走代码后 token 成本趋零。翻车面也真实：子代理缺上下文会瞎猜——给子代理的简报必须自带全部背景，因为它看不到你的对话历史。

**最小抄作业**：一条规则起步——「批量重复动作（>10 次）写脚本，判断密集的单点任务才用模型；子代理结果涉及外部副作用，必须回读验证」。

## ⑫ 验证机制与失效判据（Falsifiability）

**原理**：没有失效判据的增强 = 资产囤积。装了 200 个技能 vs 真用 30 个、养了 5 个项目 vs 全部零产出——没有事先写下的「什么算失败、什么时候清算」，沉没成本会拖着系统永远空转。

**我的做法**：所有长期投入配三件套——①事先写下的成功判据（可量化，如「到 X 日前达到 Y，否则收缩」）；②定期对账（每周自动生成账本：浏览量/转化/决策执行情况，诚实判分不含糊）；③主动收缩预案（判据触发就降级为最小维护，不恋战）。对账纪律：报告禁用「命中率」这类含糊口径，写「说对了的比例」并逐条可查。

**实测收益**：三条产品线各带判据运行，其中一条连续 5 周零增长、判据触发收缩预案——没有事先写下的判据，这种「承认投入失败」的决策永远下不了手。反向价值同样真：判据不达标主动砍，省下的资源转移给有效线。

**最小抄作业**：给每个持续投入的方向写一行：「若到 [具体日期] 仍 [具体量化判据] 未达标，则 [收缩/砍掉/换方向]」。写下来的那天起，它就替未来的你做了最难的那个决定。

# 结语：三个反直觉结论

**1. 增强的杠杆排序和大多数人做的相反。** 大家先堆工具和模型（①②⑤，容易、有爽感），实际收益排序是：⑦纪律 > ⑥知识库 > ⑨进化 > ⑫失效判据 > 其余。纪律是一，其他是零——没有纪律的 agent，配置越豪华，胡说越有说服力。

**2. 最贵的维度是「诚实」。** ⑦⑧⑫三维持续做的是同一件事：让系统自己暴露自己的错误（亲验、作废旧结论、触发判据就认输）。反直觉在于：增强系统性能最猛的单点投入，不是更强的模型，而是更狠的自我否定机制。

**3. agent 的差距本质是复利机制的差距。** 两个用同一模型的人，三个月后差距不在任何单项配置，而在：一个人每次踩坑都沉淀（⑥⑨）、每次投入都有判据（⑫）、每个错误都会被系统自己抓出来（⑦⑧）。模型是租来的，机制才是资产。
