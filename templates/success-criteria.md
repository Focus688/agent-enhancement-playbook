# 🎯 失效判据模板（Success Criteria）

> 用途：给每个持续投入的方向（项目/产品线/技能/订阅）**事先写下**可量化的成功判据与清算日期。对应 12 维中的第 ⑫ 维。
> 核心原则：**这份文件的价值在于「写下来的那天起，它就替未来的你做了最难的那个决定」。** 没有事先写下的判据，沉没成本会让你永远空转。

## 每个方向必须回答的五问

1. **为什么做**：一句话（不能写满 3 行，写不满说明还没想清楚）
2. **怎么算成功**：可量化的判据（star/付费用户/命中率/有人引用——必须是外部可观测信号，不是「我自己觉得有价值」）
3. **到什么日期清算**：具体日期，不是「三个月后」
4. **达不到怎么办**：预先写好的收缩预案（砍掉/降级为最小维护/换方向），触发即执行，不重新辩论
5. **定期对账节奏**：谁在什么频率上对账（建议每周自动账本 + 每季度人工复核判据本身是否还合理）

## 模板（复制即用）

```markdown
## [方向名] — 失效判据

- **动机**：<一句话>
- **启动日期**：YYYY-MM-DD
- **成功判据**（全部满足才算成功）：
  - 判据 A：<可量化外部信号>（当前基线：<值>）
  - 判据 B：<可量化外部信号>（当前基线：<值>）
- **清算日期**：YYYY-MM-DD（启动 + N 个月）
- **收缩预案**（判据未达标自动触发，不重新辩论）：
  - <例如：停止投入新功能，降级为每月 1 小时最小维护>
  - <例如：资产迁移至 <去向>，归档原线>
- **对账**：<每周一自动账本，字段：判据 A/B 当前值、距清算天数>
- **判据修订记录**：
  - YYYY-MM-DD：<修订内容 + 修订理由>（判据可以修订，但只能在清算日之前由「判据不合理」驱动，不得由「快到期了还没达标」驱动）
```

## 真实示例（本仓库宿主实例，已脱敏）

```markdown
## GitHub 复利资产线 — 失效判据

- 动机：把 agent 安全审计能力沉淀为公开资产（能力凭证 + 内容素材双用途）
- 启动：2026-10-10
- 成功判据：两旗舰仓库合计有机 star ≥ 20，或存在 ≥1 个外部引用（他人 PR/issue/文章引用）
- 清算日期：2027-01-12
- 收缩预案：未达标 → 停止主动推广，仓库转为纯自用维护；付费转化尝试转 Gumroad 直售优先
- 对账：每周一自动周报（organic star 数、外部引用数、距清算天数）
- 教训前置：判据写下的第一周就要开始对账——「连续 N 周零增长」的趋势信号比到期日的单点判定更早救你
```

## 已知坑

- **判据必须外部可观测**：「自己学到了很多」不算判据——它是真的，但无法清算。
- **收缩预案要写「资产去向」**：只写「砍掉」的预案永远执行不了；写明「迁移到哪」后执行阻力骤降。
- **判据修订要有防火墙**：只允许「判据本身不合理」驱动修订，禁止「快到期了但我觉得有希望」驱动——后者就是沉没成本在说话。
- **同一时间挂太多带判据的方向 = 没有判据**：建议同时活跃的带判据方向 ≤ 3 个。
